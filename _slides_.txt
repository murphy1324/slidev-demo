# 研究背景
KeyPoint：海量信息 高门槛

### 超算运行场景的典型问题 
- 平台运行数据多、来源复杂，普通用户难以快速获取所需信息
- 数据查询、统计分析和可视化通常依赖脚本或固定页面，灵活性不足
- 用户提出分析需求时，往往需要掌握数据库、命令行或图表工具，使用门槛高

# 课题目标
KeyPoint：可视化任务流 交互

### 课题目标
- 让用户以自然语言方式描述统计与分析需求
- 系统自动完成数据查询、统计分析和可视化展示
- 将智能体执行过程转化为可交互、可追踪的前端任务流程
- 降低超算运行数据分析的使用门槛，提高分析效率和可视化效果

<div><br/></div>

### 课题定位

**一个面向超算运行数据分析与可视化的自然语言交互系统。**

<!--
所以这个课题的重点是降低超算运行数据分析的使用门槛
用户只需要说出自己的任务需求，我们的系统就可以自己去做查询和分析
把任务运行的中间过程组织成清晰可见的任务流
并在关键节点与用户进行交互，更好的实现用户需求
-->

# 技术栈与系统设计

| 类别 | 技术方案 |
|---|---|
| 前端框架 | Next.js 15 + React 19 |
| 语言 | TypeScript |
| UI 组件 | MUI |
| 状态管理 | Zustand |

### 系统分层
1. 页面层：登录页、聊天页、Data Board
2. 状态层：聊天、任务、图表、鉴权状态
3. 协议层：SSE 事件解析、交互 prompt、图表事件解析
4. 展示层：Markdown、任务卡片、时间线、交互卡片、图表卡片

# 流式协议设计

### 核心事件
- `chat_begin`
- `status`
- `proof_request`
- `assistant_message_delta`
- `assistant_message`
- `tool_call`
- `tool_result`
- `exec_begin`
- `exec_output_delta`
- `exec_error`
- `exec_end`
- `chat_error`


::right::

<div><br/><br/><br/></div>

### 前端分流策略
- 最终回答：进入答案区
- 过程日志：进入任务时间线
- 用户交互：进入交互卡片
- 图表结果：进入 Data Board

<!--
同时，分流策略是系统设计里最关键的一点。
前端会把后端的应答按语义拆分，让最终回答、过程日志、用户交互、图表结果分别进入不同区域，而不全部当作文本显示
这样系统才能既能回答问题，又能展示分析过程和结果。
-->

# 总体任务流效果

### 演示场景
用户输入：**“帮我提交 agenttest 目录下任务”**

### 展示内容
- 自然语言输入
- 智能体开始规划与执行
- 前端展示任务卡片与时间线
- 用户在关键步骤进行确认或选择
- 最终得到任务提交结果

用户输入自然语言，然后智能体进行规划与执行，前端实时推送展示任务卡片与时间线

- 用户可以在关键步骤参与决策
- 前后端已经形成“任务协作式交互”闭环
