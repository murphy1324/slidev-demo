# 研究背景
KeyPoint：海量信息 高门槛

### 超算运行场景的典型问题 
- 平台运行数据多、来源复杂，普通用户难以快速获取所需信息
- 数据查询、统计分析和可视化通常依赖脚本或固定页面，灵活性不足
- 用户提出分析需求时，往往需要掌握数据库、命令行或图表工具，使用门槛高

# 课题目标
KeyPoint：可视化任务流 交互

### 课题目标
- 让用户以自然语言方式描述统计与分析需求
- 系统自动完成数据查询、统计分析和可视化展示
- 将智能体执行过程转化为可交互、可追踪的前端任务流程
- 降低超算运行数据分析的使用门槛，提高分析效率和可视化效果

<div><br/></div>

### 课题定位

**一个面向超算运行数据分析与可视化的自然语言交互系统。**

<!--
这个课题的核心目标是降低使用门槛。

用户只需要用自然语言描述需求，
系统就可以自动完成数据查询、分析和可视化。

同时，把执行过程组织成一个可视化的任务流，
并在关键步骤与用户进行交互。
-->

# 技术栈与系统设计

### 技术栈

| 类别 | 技术方案 |
|---|---|
| 前端框架 | Next.js 15 + React 19 |
| 语言 | TypeScript |
| UI 组件 | MUI |
| 状态管理 | Zustand |
| 流式协议 | `@microsoft/fetch-event-source` |
| 图表渲染 | Vega-Lite / vega-embed |
| 部署方式 | 静态导出 + Nginx |

::right::

<div><br/></div>
<div><br/></div>

### 系统分层
1. 页面层：登录页、聊天页、Data Board
2. 状态层：聊天、任务、图表、鉴权状态
3. 协议层：SSE 事件解析、交互 prompt、图表事件解析
4. 展示层：Markdown、任务卡片、时间线、交互卡片、图表卡片

# 流式协议设计

### 核心事件

- `status`
- `proof_request`
- `assistant_message_delta`
- `assistant_message`
- `tool_call`
- `tool_result`
- `exec_begin`
- `exec_output_delta`
- `exec_error`
- `exec_end`
- `chat_error`

<div><br/></div>
<div><br/></div>


### 前端分流策略
- 最终回答：进入答案区
- 过程日志：进入任务时间线
- 用户交互：进入交互卡片
- 图表结果：进入 Data Board

# 交互式任务流

<div><br/></div>

### 用户参与决策，协作式执行任务
- 表单交互
- 文件选择
- 参数选择
- 混合输入

<div><br/></div>


::right::

<div class="border rounded-xl p-4 mt-8 opacity-70">图片/视频占位</div>

<!--
系统不是单向问答，
而是协作式执行。

智能体会分析得到该任务的关键步骤，在关键步骤申请用户的确认和选择，并可能给到用户一个推荐

比如，对于这个输入智能体会在选择可执行文件和资源配置这两步请求用户交互

同时给出一些备选项，对于每个node它有一个推荐的配置，用户可以选择使用这个推荐的配置也可以自己设置一个

配置的推荐算法后续会有说明

这样就让用户参与到了关键步骤中，
形成了闭环。
-->
